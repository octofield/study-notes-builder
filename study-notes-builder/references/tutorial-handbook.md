# A. 完整教學手冊

適用於使用者想從零學會一個主題，並要求「完整到不能再完整」的情境。預設要的是系統化的全貌，不是精華摘要，成品通常是離線單檔 HTML 加互動測驗。

## 目錄

1. 範圍與分部
2. 每章固定骨架
3. 必備的章節類型
4. 「只講差異」的擴充
5. 測驗設計
6. 製作流程

## 1. 範圍與分部

先把主題切成由底到頂的幾個部分，再切章。以一個程式語言的教學為例，可以分成：

- 準備：這個東西是什麼、怎麼跑
- 語言核心：變數、型別、運算子、控制流程、函式、物件、集合、錯誤處理等
- 進階機制：非同步、模組、元編程等
- 執行環境：瀏覽器、伺服器端、網路與儲存
- 進階與實務：記憶體與效能、語法演進、經典陷阱、工程實務與學習路線、練習題

換主題時沿用這個思路：核心 → 進階機制 → 執行環境 → 實務與陷阱。章節順序要讓每章只依賴前面講過的東西。

## 2. 每章固定骨架

**觀念 → 規則 → 範例 → 陷阱**

- 觀念：這章要解決什麼問題、心智模型是什麼
- 規則：用表格或條列整理規則，一眼可查（程式類主題就是語法規則）
- 範例：可執行或可手算的小範例，註解寫「為什麼」；常用的放成速查表
- 陷阱：這章最容易踩的坑與正確做法

理由：固定骨架讓讀者複習時知道往哪找，也逼自己每章都把陷阱想過一遍。

## 3. 必備的章節類型

除了主題本身的章節，手冊最後幾章要有：

- 演進年表（依版本或時期列出新增與變化）
- 經典陷阱集，集中整理最常見的錯誤
- 實務與學習路線，告訴讀者學完之後往哪走
- 練習題，涵蓋各章重點

## 4. 「只講差異」的擴充

讀者已經會前一個主題時，後一個相近的主題只講差異。例如已經學過某個語言，再學它的超集或相近語言，就只談不同之處：核心概念的差別、新增的機制、常見陷阱、與既有工具的整合。理由：重講讀者已會的東西，會稀釋重點。

## 5. 測驗設計

- 題型：單選、多選、是非
- 位置：每章末，長章節在中段加檢查點
- 規模：每章約 3–5 題，視章節長短調整
- 互動：作答後立即回饋，對錯用顏色標示（對 `#17805A`、錯 `#A8332A`）；多選題要標出漏選的選項；每組顯示分數；可重試
- 資料與正文分開存放（例如獨立的題庫檔），在 Markdown 裡用 `<!--QUIZ:key-->` 標記位置，轉成 HTML 時替換成互動卡片。理由：改題目不必動正文，也方便檢查答案正確性
- 每題的解析要說明「為什麼其他選項錯」，不是只給答案

## 6. 製作流程

1. 列出全部章節與每章要涵蓋的重點，請使用者確認
2. 分塊寫 Markdown（用 `cat >> file << 'CHUNK'` 接續附加，避免一次輸出被截斷）
3. 追加的部分另開一輪，接在後面
4. 寫題庫，用標記注入
5. 轉成單檔離線 HTML，細節見 `html-engineering.md`
6. 驗證：外部請求為零、程式碼區塊都有上色、測驗可操作、深淺色主題都可讀
