# D. 長影片轉教學文件

適用於把數小時的教學影片、課程錄影整理成教學文件，必要時再做成離線互動 HTML 手冊。

## 目錄

1. 能做與不能做
2. 取得文字來源
3. 分章策略
4. 給 NotebookLM 的兩步驟提示詞
5. 合併與核對
6. 最終輸出

## 1. 能做與不能做

Claude 無法直接「看」或「聽」影片，只能處理文字。所以一定要先把影片變成文字（逐字稿或字幕）。

三個限制要主動告訴使用者：

- 逐字稿辨識錯誤會直接影響成品，技術術語、指令、程式碼最容易錯，需要抽查
- 講者在畫面上操作卻沒有用口語說明的內容，只看逐字稿會漏掉，需要截圖或描述補充
- 不會憑空補上影片沒講的內容；使用者要求補充背景知識時，明確標示哪些是補充

## 2. 取得文字來源

- YouTube：有字幕就把字幕文字貼進來
- 自己的影片檔：先用語音轉文字工具產生逐字稿，例如 Whisper（本機免費）
- 有投影片的課程：逐字稿加上投影片或截圖，把畫面上的程式碼和圖表整合進去

## 3. 分章策略

一小時的中文逐字稿約 7,000–10,000 字，數小時的影片單次放不進對話。

1. 先切成每段 30–60 分鐘，對應一個章節或主題
2. 每一段整理成固定結構（見第 4 節）
3. 全部完成後合併、統一格式、補目錄與前後章銜接

## 4. 給 NotebookLM 的兩步驟提示詞

NotebookLM 的優勢是只根據上傳的來源回答，不容易杜撰，適合這類整理。使用者習慣分工使用不同 AI 工具，所以需要時直接提供這組提示詞，並依影片主題微調（例如強化公式推導或程式碼說明）。

**第一步：章節大綱**（先不寫正文）

```
請根據來源中的完整影片內容，先不要寫正文，只做以下事情：
1. 依照講者實際的教學順序，把整部影片切成若干個章節（每章約對應 30 至 60 分鐘的內容）。
2. 每個章節請列出：章節編號、章節標題、涵蓋的主要概念（3 至 8 點）、大約對應的影片時間範圍。
3. 最後列出整部影片中反覆出現的專有名詞、工具、指令或公式，作為之後統一用詞的對照表。
輸出語言：繁體中文。只根據來源內容，不要加入來源中沒有出現的資訊。
```

**第二步：逐章教學文件**（確認大綱後，每次換章節名稱重複使用）

```
請根據來源內容，將「第 N 章：〈章節標題〉」整理成一份詳細的教學文件。
【角色】你是一位技術文件撰寫者，目標是讓沒看過影片的讀者，也能只靠這份文件學會這一章的內容。
【文件結構】依序包含：
1. 本章學習目標
2. 前置知識（講者有提到的才寫）
3. 核心概念說明：先給定義，再用講者的例子或比喻解釋
4. 逐步操作或推導流程：用「步驟 1、步驟 2…」編號，說明做什麼、為什麼這樣做
5. 公式與程式碼：公式獨立列出並說明符號；程式碼放在程式碼區塊，保留講者的原始寫法並逐段說明
6. 範例：完整保留講者示範的例子，附上輸入、過程與結果
7. 常見錯誤與講者特別提醒的注意事項
8. 本章重點摘要（5 條以內）
9. 自我檢查練習題（3 至 5 題，根據本章內容出題）
【規則】
- 輸出語言：繁體中文；專有名詞第一次出現時附上英文原文。
- 嚴格依據來源內容，不要補充影片沒講的知識；來源不清楚或矛盾處標註「（來源此處不清楚）」，不要自行猜測。
- 講者在畫面上操作而沒有口語說明時，標註「（此處為畫面操作，需對照影片）」並註明大約時間點。
- 每個重要段落標註對應的影片時間點，方便回頭查證。
- 內容寫得詳細完整，寧可長一點，也不要為了簡短而省略步驟。
- 用詞與先前產生的專有名詞對照表保持一致。
```

使用小技巧：單章被截斷時回覆「請從上次中斷處繼續」；全部章節完成後，把內容貼回來給 Claude 統一格式、補目錄、合併。

## 5. 合併與核對

- 合併後逐一核對章節是否涵蓋影片的完整時間軸，沒有缺漏也沒有重複。核對後章數可能和原先規劃的不同，這時重新編號並更新目錄與前後章的銜接
- 統一格式、專有名詞與編號，補目錄與章節間的銜接
- 抽查指令與程式碼，對照時間點回去確認

## 6. 最終輸出

使用者要的是離線互動 HTML 手冊，除了一般手冊功能外，還有：

- 章節閱讀進度追蹤（用 localStorage 記錄時要包 try/catch，取不到儲存空間時頁面仍要正常顯示）
- 全文搜尋
- 時間軸導覽：每個段落的影片時間點可點選或列出，方便回影片查證

HTML 實作細節見 `html-engineering.md`。
