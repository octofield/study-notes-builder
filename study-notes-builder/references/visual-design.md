# 美觀、易讀、圖文並茂

使用者明確要求學習材料「美觀、易於閱讀、圖文並茂」。這不是裝飾：好的版面和圖，是讓人願意讀完、讀得懂、複習時找得到的原因。所有形式都適用。

## 1. 圖文並茂的判準

每個主要小節都要問：「這裡有沒有一個圖或表，能讓讀者比讀文字更快懂？」有就一定要放，沒有就不要硬塞。圖的價值在於承擔解釋，純裝飾的插圖會稀釋重點，也會讓人分心。

- 概念有空間、順序、層級、因果關係時，圖幾乎一定比文字清楚
- 同一個概念用文字講超過一段，就考慮改成圖加簡短說明
- 一頁全是文字牆，就是訊號：該拆成圖、表、卡片
- 來源（講義、投影片）裡有的圖，一律重畫並放進來

## 2. 內容類型對應的圖

| 內容 | 適合的呈現 |
|---|---|
| 流程、演算法步驟、決策 | 流程圖；演算法加逐步動畫 |
| 系統、架構、模組關係 | 方塊與箭頭的架構圖，分層上色 |
| 時間順序、通訊協定、非同步 | 時序圖、時間軸 |
| 資料結構、陣列與指標、樹與圖 | 狀態圖，每一步畫出當下的結構 |
| 數學關係、函數、分布 | 座標圖或示意曲線，標出關鍵點 |
| 比較多個選項 | 對照表，欄位一致、重點加色 |
| 規則、語法、速查 | 表格，不要寫成一長串條列 |
| 定義、定理、警告、提示 | 有色邊框的卡片，不同類型用不同顏色 |
| 數據與趨勢 | 圖表，附明確標題與單位 |
| 影片教學的畫面操作 | 逐步截圖或示意圖，標註時間點 |

## 3. 圖的製作方式

Claude 做不出寫實照片，也不應該用不相干的圖湊數。能做、而且最適合學習材料的是：

- **SVG**：示意圖、結構圖、狀態圖、圖示，向量格式可無限放大，也能跟著深淺色主題換色。首選
- **HTML／CSS**：表格、卡片、時間軸、簡單的方塊圖
- **Mermaid**：流程圖、時序圖、狀態機、ER 圖，純文字、易修改
- **圖表**：資料類用 Python（matplotlib）或圖表函式庫，輸出要附標題與單位
- **互動式圖**：狀態逐步變化的內容用可點擊動畫（見 `lecture-explainer.md`）

使用者要寫實照片或藝術風格插圖時，這超出 Claude 能直接做的範圍，建議用專門的圖像生成工具，並可代寫提示詞。不要用網路找來的圖直接嵌入材料，版權與離線都會有問題；使用者自己提供的圖才放進去。

SVG 畫完要轉成 PNG（例如 `cairosvg`）親眼檢查：文字有沒有被切掉、箭頭有沒有指對、顏色在深淺色下是否清楚。

## 4. 讓圖與文字互相配合

- **每張圖有編號與說明**：「圖 3-2　二分搜尋的區間縮小過程」，並在正文裡明確提到它
- **圖緊貼對應的文字**，不要集中放到文末
- **圖要自己說得通**：標籤直接寫在圖上，不要讓讀者在圖例和圖之間來回找
- **標出重點**：用顏色、粗細或標註框指出「這一步改變了什麼」，不要讓讀者自己找
- **一張圖只講一件事**；太複雜就拆成兩張或做成逐步顯示
- **替代文字**：每張圖加 `role="img"` 與 `aria-label`（或 `<title>`），說明圖在表達什麼
- 圖的顏色用法在全篇一致，例如「新增」永遠是同一個顏色

## 5. 易讀的版面

- 內文 17px 以上，行高約 1.8，段落寬度約 760px，不要整頁撐滿
- 留白充足，段落短，一段一個重點
- 標題層級分明，大小與粗細有明顯差距，章節編號清楚
- 長內容用小標題、條列、表格切開，但不要為了好看而把連貫的推理拆成零碎的條列
- 重要的東西（定義、公式、警告）用卡片或色塊與正文區隔，其他地方保持安靜
- 程式碼用等寬字體、上色，並與正文有明顯的底色差異
- 公式獨立成行並置中，符號說明放在公式下方
- 表格欄位對齊，數字靠右，寬表格在自己的容器內橫向捲動
- 手機上也要可讀：單欄、字級夠大、點擊目標夠大

## 6. 配色與主題

- 一個主色（強調色）加一組中性色，其他顏色只用在有語意的地方（對錯、警告、分類）
- 避免純白底配純黑字，用柔和的底色與深灰字，降低長時間閱讀的疲勞
- 對比要夠：正文與背景對比足以閱讀，淺色與深色主題都要檢查
- 不要只靠顏色傳遞資訊，搭配文字、圖示或形狀，色盲讀者與黑白列印才看得懂
- 考前大抄這類高密度材料，改用「分章配色」，同一章同一個顏色，方便快速定位

## 7. 交付前自查

- 每個主要小節有沒有至少一個圖、表或卡片？有哪些小節是純文字牆？
- 來源的圖是不是全都重畫並放進來了？
- 每張圖都有編號、說明、正文引用、替代文字嗎？
- 手機寬度（約 390px）與桌機寬度各截圖看過嗎？
- 深色與淺色主題各看過嗎？
- 黑白列印或灰階下還看得懂嗎？
