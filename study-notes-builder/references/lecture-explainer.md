# B. 講義解說網頁

適用於使用者手上有講義或 PDF，要把它做成看得懂、可以取代原講義的單檔 HTML。常見的演進是：先要一份提示詞模板，再要求直接執行，接著要求加上互動動畫，最後要求「內容要完整，我不想回去對照講義，連圖片也要」。所以預設就做到最後那個標準。

## 目錄

1. 內容結構
2. 小節骨架
3. 逐步動畫
4. 圖的處理
5. 來源對照表
6. 版面設計
7. 製作與驗證

## 1. 內容結構

1. 開頭 3–5 句總覽：這份文件在講什麼、解決什麼問題
2. 重點速覽表：主題、核心敘述、用途或手法、複雜度（若適用）
3. 依來源章節拆成小節
4. 結尾：重點回顧清單，加 5 題可折疊的自我檢測

總覽要點出貫穿全篇的主軸，讀者才知道各節在做同一件事。

## 2. 小節骨架

每個小節依序包含：

a. **直覺說明**：先用生活化比喻講為什麼要這樣做
b. **逐步流程**：編號步驟，關鍵步驟說明為什麼需要
c. **公式推導**：每條公式獨立成行，逐一解釋符號，推導不跳步
d. **虛擬碼或程式碼**：附行號與逐行註解
e. **手算範例**：用一組小資料，以表格列出每一輪的狀態變化
f. **複雜度分析**：最好、平均、最壞，並說明推導理由
g. **常見誤解與易錯點**

不是每個小節都需要全部七項，數學證明類的小節把 c 和 e 當重點。

## 3. 逐步動畫

排序、搜尋、遞迴展開、迴圈不變式、資料結構操作這類「狀態逐步改變」的內容，做成可點擊的動畫。

- 控制：上一步、下一步（或播放）、重設，並顯示「步驟 n/總數」
- 每一步高亮「這一步改變了什麼」，並用一句話說明為什麼
- 把整個過程預先算成步驟陣列，再逐步顯示。理由：邏輯與畫面分離，才好檢查每一步是否正確
- 動畫各自獨立成函式，不互相依賴

## 4. 圖的處理

- 來源裡的圖全部用 SVG 重畫，不依賴外部圖片
- 畫完用 `cairosvg` 轉成 PNG 親眼檢查。重畫時容易出現的錯誤，例如被移除的元素還畫在圖上、標籤與圖形對不上，只有轉成圖片看過才會發現
- 圖旁邊標明對應來源的圖號

## 5. 來源對照表

在文末附一張表，把來源的每個章節、定理、引理、圖，對應到本文件的錨點。理由：使用者要能確認「原講義的東西我這裡都有」。

## 6. 版面設計

- 字體：內文 Noto Sans TC，程式碼 JetBrains Mono；行高 1.8、內文 17px 以上、段落最大寬度約 760px
- 左側 sticky 目錄，標示目前閱讀位置；手機版改成可收合選單，並加閱讀進度條
- 配色柔和（避免純白純黑），單一強調色；重要定義用有色邊框卡片
- 深色模式；列印成 PDF 不跑版
- 數學用 KaTeX，程式碼用 highlight.js 並附一鍵複製

## 7. 製作與驗證

- 分成多個檔案撰寫（`part1.html`、`part2.html`……）再串接。理由：單一 HTML 很長，一次輸出容易被截斷
- 用 `python scripts/verify_html.py` 檢查標籤、錨點、重複 id、內嵌 JS 語法
- 所有 KaTeX 式子用 `katex.renderToString(..., {throwOnError: true})` 逐一驗證
- 來源是 OCR 的時候，遇到有歧義的符號（分數、上下標、相似字元）要寫出判讀依據，並在最後的回覆中請使用者對照原始投影片確認
- 外部資源：這個形式預設可用 CDN（KaTeX、highlight.js），但要在回覆中告知「需要連網」；使用者要離線時改走 `html-engineering.md` 的離線做法
