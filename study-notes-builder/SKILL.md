# 學習材料撰寫指引

這份 skill 整理自使用者過去做過的幾種學習材料（教學手冊、講義解說網頁、考前大抄、影片轉教學文件）。它們有一個共同的目標：**讀者只靠這份材料就能學會，不用回頭翻原始講義或影片。**

## 先決定形式

| 使用者的情境 | 形式 | 先讀 |
|---|---|---|
| 想從零學會一個主題，要求完整、系統化 | A 完整教學手冊 | `references/tutorial-handbook.md` |
| 手上有講義或 PDF，要看得懂、取代原講義 | B 講義解說網頁 | `references/lecture-explainer.md` |
| 考試只能帶一張紙 | C 考前大抄 | `references/cheat-sheet.md` |
| 來源是影片、長逐字稿 | D 影片轉教學文件 | `references/video-to-doc.md` |
| 任何要輸出 HTML 的形式 | 一律另外讀 | `references/html-engineering.md` |
| 所有形式（版面、配圖、配色） | 一律另外讀 | `references/visual-design.md` |

如果使用者只要一份可編輯、可分享的普通文件（不需要互動、離線或精準排版），改用環境提供的文件工具或其他文件 skill，不必走這份。形式不明確時，先依情境挑最合理的一種並說明，不要一次問一堆問題；真的需要問，只問「誰要讀、在哪裡用（手機、列印、考場）」。

## 共通原則

每一條後面的理由很重要，遇到沒列到的情況時，照理由推論。

1. **語言**：繁體中文（台灣用語）。專有名詞第一次出現寫成「中文（English）」，之後用中文即可，並維持全篇用詞一致。理由：使用者會拿來複習與考試，用詞飄移會造成混淆。
2. **忠於來源**：有來源（PDF、逐字稿）時，內容以來源為準。來源沒有、自己補上的說明，標上「補充」。來源看不清楚或 OCR 不確定的地方，寫出自己的判讀依據，並在最後回覆時請使用者核對。理由：學習材料裡的錯誤會被當成事實背起來，所以寧可標示不確定，也不要悄悄猜一個。
3. **自足**：使用者說過「不想回去對照講義」。所以來源裡的圖要重畫（用 SVG），表格裡一筆帶過的建構細節要展開，並附一張「來源章節與本文件錨點」對照表。
4. **解釋方式**：一步一步講，不跳步。每條公式獨立成行，逐一說明符號意義，推導寫出每一步的依據。先給直覺或比喻，再給嚴格說法。
5. **固定的章節骨架**：同一份材料裡每章結構一致，讀者才知道去哪裡找東西。各形式的骨架見對應的 reference。
6. **練習與自我檢測**：每章附練習或測驗，並列出常見誤解與易錯點。理由：被動閱讀的留存率低，複習材料要能讓人自己測試。
7. **大文件分段做**：超過一次輸出能容納的量時，先給大綱請使用者確認，再逐章或逐部分撰寫，最後合併、補目錄、核對是否涵蓋來源的全部內容。分段檔案最後用指令串接，避免單次輸出被截斷。
8. **驗證後才說完成**：HTML 用 `scripts/verify_html.py` 檢查，圖與版面實際轉成圖片看過。沒做的驗證不要宣稱做過。
9. **美觀、易讀、圖文並茂**：使用者明確要求。每個主要小節都問「有沒有一個圖或表能比文字更快讓人懂」，有就放；來源裡的圖全部重畫；圖要有編號、說明、替代文字，並在正文中被引用；版面留白充足、層級分明、配色柔和且深淺色主題都清楚。圖要承擔解釋，不要純裝飾。理由：材料好不好看、好不好讀，決定使用者會不會真的拿來複習。細節與自查清單見 `references/visual-design.md`。
10. **誠實回報**：最後的回覆簡短說明做了什麼、有哪些判斷點、哪些地方需要使用者對照原始資料核對。發現使用者自己的作業或筆記有疑似錯誤時，明確指出並建議對照官方解答。

## 工作流程

1. **釐清限制**：來源檔在哪、讀者是誰、要在哪裡用（手機、列印、考場）、是否需要離線、有沒有考試規則或頁數限制。
2. **完整讀完來源**：PDF 用 `pdf-reading` 或 `file-reading` 這類 skill 讀；影片先確認有沒有逐字稿。記下 OCR 或辨識不確定的位置。
3. **長文件先出大綱**：章節、對應來源位置、預計的互動元件，請使用者確認。
4. **分段撰寫**：照對應 reference 的骨架。
5. **組裝與驗證**：HTML 跑 `python scripts/verify_html.py <檔案>`（也會提醒哪些小節缺圖表）；PDF 轉成圖片逐頁看；用 `visual-design.md` 第 7 節的清單自查。
6. **交付**：檔案放到輸出目錄，依環境規則發佈或呈現。
7. **回報**：見共通原則 10。

## 使用者過去常見的追加要求

這些在過去的對話中重複出現，所以可以一開始就預設做好，省掉來回：

- 「內容要完整，我不想回去對照講義，連圖片也要」→ 預設重畫來源的圖、展開細節、附對照表
- 「分章配色、標題縮小、簡單例子壓縮」→ 大抄類預設分章配色與緊湊排版
- 「加入作業內容」→ 作業的正確推導補進材料，使用者答案有疑點時標出來
- 「美觀、易讀、圖文並茂」→ 預設每個主要小節配圖或表，版面與配色依 `visual-design.md`
- 「加互動」→ 狀態逐步改變的內容（如演算法）加逐步動畫，章節加測驗卡
- 「改成離線可用」→ 不依賴外部資源，並實際驗證零外部請求
